# cherry-studio-kcfix

本仓库是 Cherry Studio 的个人使用改造版，不向官方仓库提交 PR。用户已授权在本 fork 的 [Releases](https://github.com/KC-Casey/cherry-studio-kcfix/releases) 发布 Windows x64 便携预发布版，供下载实测；这不是 Cherry Studio 官方发行版。发布授权不代表构建或运行验证已经完成，具体产物和验证结果以对应 Release 说明为准。

## 开发运行与数据

使用 `pnpm dev:kcfix` 启动。该入口固定将 `CS_DEV_PROFILE_ROOT` 设为本工作副本下的 `.context/kcfix-profile/`，开发数据、启动配置、日志和临时文件均由已有 profile-root 机制放在该目录下。不自动导入、迁移或删除原版数据。首次运行需要重新配置第三方提供商。

不要用真实用户目录做开发测试。一般 `pnpm dev` 仍遵循上游开发启动规则；如自行启动，必须明确设置绝对路径 `CS_DEV_PROFILE_ROOT`。

安装版不保证与原版并存，未进行专门并存测试。实际路径遵循现有逻辑：

- BootConfig 默认仍在用户主目录下 `.cherrystudio/boot-config.json`。
- 如 BootConfig 对当前可执行文件配置了有效的 `app.user_data_path`，优先使用该目录。
- 否则由 Electron 按包名 `cherry-studio-kcfix` 选择系统用户数据目录；Windows 便携版使用便携程序所在目录下的 `data`。
- 日志由现有路径注册器解析；开发专用入口的日志固定在隔离目录的 `logs` 下。

因此更改应用名称并不意味着所有发行版数据都已隔离。首次运行前应备份已有目录并核对路径。本次开发未读取或修改用户电脑上的原版数据。

### 将主要数据存到其他磁盘

打包后的应用已有目录选择功能，无需将数据库和图片长期放在 C 盘：

1. 打开 **设置 → 数据 → 数据目录 → 应用数据 → 修改目录**。
2. 选择专用的新目录或空目录，例如 `D:\cherry-studio-kcfix-data`，不要选择磁盘根目录 `D:\`、原目录的父目录或子目录。先备份重要数据，并为完整复制预留足够空间。
3. 核对旧、新路径，保留“复制数据”选项后确认，等待复制和自动重启完成；过程中可能重启多次，不要强行关闭或移动目录。
4. 重启后再次核对“应用数据”路径，并检查聊天、图片和设置。原目录会保留，不会自动删除。

复制范围是整个应用用户数据目录，包括 SQLite 数据库、保存的图片和文件、主要设置及 Chromium 存储。非空目标只允许切换到该目录，不会合并或覆盖其中的数据；若想保留当前数据，请使用新目录或空目录并复制。开发模式不执行此迁移。

便携程序在没有有效自定义路径时，默认使用程序旁的 `data`；已保存的有效自定义路径优先。便携不等于所有文件都跟随程序：启动路径映射仍默认写入 `%USERPROFILE%\.cherrystudio\boot-config.json`，MCP 配置、部分授权信息及工具文件仍可能位于该主目录下的 `.cherrystudio`；日志、系统临时文件和崩溃记录也可能留在 C 盘。此功能迁移主要数据，不承诺零 C 盘写入，也不保证换电脑后保留所有配置。

## 私有改造边界

移除 Cherry 自有账号、订阅和云服务入口，保留第三方提供商的 API 密钥和 OAuth。上游更新查询、下载和安装均不可用，避免自动更新把改造版替换回原版。版本更新须自行核对代码并构建。

图像编辑沿用现有绘图和提供商请求流程。历史输出可用作新的编辑输入；原始提示词只作记录，本次编辑指令单独发送。分支记录保留父图和执行信息，不保存 API 密钥或完整请求。尺寸、质量是否支持取决于所选模型，不能将未知实际响应参数当作已知。

## 验证范围

只运行改动相关的检查，不以单元测试代替真实提供商调用、Electron 视觉检查或安装包验证。开发依赖安装可使用 ONNX 官方支持的 `ONNXRUNTIME_NODE_INSTALL=skip` 跳过该可选原生运行时下载；此时不声称本地 ONNX 推理经过验证。付费模型请求需要单独确认，不使用用户凭证作自动测试。
