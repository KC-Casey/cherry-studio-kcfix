# Agent Note: cherry-studio-kcfix 图像编辑工作台

Status: proposed

[English](2026-11-04-kc-image-workbench.md) | 中文

## Problem

私有改造版命名为 cherry-studio-kcfix。用户已取消同时安装和并存验证要求，通常只会安装一种。开发过程不得修改用户已有数据。目前应用共用原版的应用 ID、协议注册、启动配置目录和更新渠道。图像历史保存提示词和文件，但尚未持久化足够的编辑谱系和执行参数来复现分支。

## Proposal

使用 cherry-studio-kcfix 作为应用名称。这是非公开发行的私有改造版；同时安装、独立安装身份、替代协议注册及专门并存测试不在范围内。开发运行必须明确设置 CS_DEV_PROFILE_ROOT，不读取或修改用户已有目录。在运行安装版之前，说明实际生效的 userData、BootConfig、日志路径，以及与原版共享目录的风险。开发任务不自动复制、迁移或删除用户目录。禁用原版自动更新安装，避免私有改造版被替换。保留现有提供商 OAuth 回调和内部文件 URL。

移除 Cherry 自有账号、订阅、账单、云模型与云服务入口，以及这些入口背后的启动请求。保留第三方提供商 API 密钥、提供商 OAuth、本地资料设置和无关本地功能。修改服务注册前追踪 CherryCloudService 的全部使用者。不移除通用 OAuth 基础设施，也不将切换 CN 版本当作隔离方案。

扩展现有绘图页面和规范化生成流程。左侧显示谱系缩略图，中间显示当前图像并可对照父图，底部分开显示原始提示词记录和本次编辑指令，右侧显示模型、尺寸、质量及参考图槽位。选择任意历史输出即选定下一次输入的确切图像。编辑创建子节点，不修改父节点；选中旧图可创建另一条分支。原始提示词仅作元数据，绝不隐式拼入编辑指令。

使用现有 SQLite/DataApi 和 FileEntry 体系持久化只追加的执行记录，通过新增向前迁移实现。记录父绘图及父输出文件 ID、所选模型和提供商、原始提示词、本次指令、请求及已知实际尺寸/质量、参考图 ID、执行模式、实际适配器和操作标识。在主进程请求边界获取实际接口信息，不根据模型名猜测。仅保存允许列表中的元数据，不保存令牌、请求头、原始请求对象、含凭证 URL 或提供商密钥。未知实际值明确保留为未知。旧绘图可读，不伪造谱系。

标注作为可独立验证的增量：保留不可变原图字节和矢量覆盖层，仅在明确应用时创建独立派生图。清晰标识原图、标注预览及已渲染标注输入。不偷偷发送仅供显示的覆盖层，也不忽略用户已明确应用的标注。

按依赖顺序实施：名称与安全开发目录；移除 Cherry 自有入口；持久化和请求记录；画布与分支；可选标注。不包含推送、合并、发布或公开安装包。本提案尚未获批，也不声称已实现。

## Alternatives considered

- 最新用户要求排除了完整并存改造。仅改名称不能证明数据隔离，应报告实际路径。
- 移除全部登录或 OAuth 代码会破坏明确要求保留的第三方提供商功能。
- 仅用 localStorage 保存画布会丢失可靠历史，并绕过已有数据库与文件生命周期。
- 每次编辑重用原始提示词会改变用户指令，因此排除该方案。

## Acceptance criteria

- AC1 — 应用命名为 cherry-studio-kcfix；文档说明安装版实际数据路径及共享目录风险，不声称保证并存，也不进行专门并存测试。 (verification: unit and docs gate)
- AC2 — 开发运行使用明确隔离目录，不读取或修改用户已有数据；不提供原版更新安装。 (verification: unit and Electron)
- AC3 — Cherry 账号、订阅、云服务入口及其启动网络请求消失，第三方 API 密钥和 OAuth 设置仍可用。 (verification: renderer and Electron)
- AC4 — 选择任意旧节点输出会发送该确切文件及本次编辑指令；原始提示词仍可见，但不进入编辑请求文本。 (verification: renderer and unit)
- AC5 — 从同一历史图像编辑两次会产生不同子节点，重启后仍保留，父节点和其他分支不变。 (verification: database and Electron)
- AC6 — 画布提供谱系、当前图、父图对照、原始提示词、指令、模型、尺寸、质量和参考图槽位，并按能力校验。 (verification: renderer and Electron)
- AC7 — 持久化记录标识父输出与实际执行接口，保存模型、提示词、指令、尺寸和质量，不包含凭证或含密钥 URL。 (verification: unit and database)
- AC8 — 已有数据的数据库可向前迁移且不丢数据；旧绘图可查看，不伪造缺失的谱系。 (verification: database)
- AC9 — 取消、失败、重复提交和选择变化不会把结果关联到错误父图，也不会重复保存已完成记录。 (verification: renderer and database)
- AC10 — 若交付标注，原图字节保持不变，明确应用后才发送有标识的派生图；否则明确报告标注延期。 (verification: renderer and Electron)

## Risks

提供商能力和 OAuth 回调限制可能影响可用编辑模型。安装版并存和公开发行不属于验收要求。真实提供商执行需要配置凭证，付费请求需授权。未实际执行时，不声称已验证安装版运行或安装包。当前仓库要求实质实现前获得对提案的明确人工批准；批准方案和授权发布是不同决定。
